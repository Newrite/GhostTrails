# API v1

## C++

Скопировать `include/GhostTrailsAPI.h` в потребителя. Никакая import library,
BMI или линковка с GhostTrails не требуется. Получать интерфейс на SKSE
`kPostLoad` или позднее, когда DLL загружена. Отсутствие/неподдерживаемая
версия дают `nullptr`. Интерфейс заимствован до завершения процесса;
удалять его, выгружать DLL и передавать через ABI STL-контейнеры не нужно.

```cpp
auto* trails = GhostTrailsAPI::RequestPluginAPI();
if (!trails || !actor) return;

GhostTrailsAPI::SpawnOptions options;
options.appearance = {0.3f, 0.8f, 1.0f, 0.6f, 2.0f, 3.0f};
options.count = 6;
options.interval = 0.045f;
options.lifetime = 0.4f;
options.retryWindow = 0.15f;
options.spawnWindow = 0.3f;

GhostTrailsAPI::RequestID id{};
const auto result = trails->Spawn(actor->GetHandle().native_handle(), &options, &id);
// Accepted: retain id, inspect GetStatus later, then Release after the visual fades.
```

`ActorHandle` — числовое значение **BS ActorHandle**, не FormID. Сырой Actor
достаточен только на момент получения handle в правильном движковом контексте.
Методы API можно вызывать с любого потока. Они копируют переданные значения;
все операции над движком выполняются позже на главном потоке.
Указатели на входные/выходные структуры должны быть валидны во время вызова.
Экспорт `RequestPluginAPI(InterfaceVersion::V1)` возвращает `IVGhostTrails1*`.
V1 фиксирует порядок виртуальных методов, размеры и значения полей;
будущие несовместимые изменения потребуют нового номера интерфейса.

| Операция | Контракт |
|---|---|
| `Spawn(handle, options, &id)` | Конечная серия из `count` попыток создания; положительный ID при Accepted |
| `Prepare(handle, slots, &id)` | Довести доступную емкость пула до `slots`, постепенно; не показывать фантомов |
| `GetStatus(id, &status)` | Скопировать сохраненный результат; запросить с любого потока |
| `SetAppearance(id, &look)` | Изменить следующие фантомы серии; уже показанные сохраняют свой цвет |
| `Cancel(id)` | На следующем обновлении остановить серию и убрать ее показанные фантомы |
| `Release(id)` | Также удалить сохраненный результат и освободить место для запросов |
| `SetDefaultAppearance(&look)` / `GetDefaultAppearance()` | Потокобезопасная настройка полного оформления по умолчанию |

Результат `Accepted` означает прием команды. Он не означает готовый фантом.
Готовность и ошибки определяются по `Status`. Изменение цвета одновременно
с уже выполняющимся захватом может примениться со следующего обновления;
чтобы гарантировать цвет конкретного фантома, вызвать `Spawn` с `count=1`
и нужным `appearance`. C++ использует default look явно:
`options.appearance = trails->GetDefaultAppearance()`.

Цвет RGB и alpha — конечные числа в `[0,1]`; intensity и rimPower — конечные
неотрицательные числа. `rimPower=0` отключает ободок. `count` от 1 до INT32_MAX;
`interval>=0`, `lifetime>0`, `retryWindow>=0`, `spawnWindow>=0` — конечные
секунды игрового времени. Интервал 0 все равно дает максимум один фантом
запроса за кадр. После долгого кадра исторические позы не догоняются пачкой.
Время жизни начинается при успешном присоединении к сцене. `spawnWindow=0`
не ограничивает общую длительность серии; положительный window отсчитывается
от первого обслуживания запроса главным потоком и прекращает новые фантомы,
сохраняя fade уже созданных. Prepare ограничен SlotsPerActor и считает уже
имеющиеся слоты готовой емкости; активный слот может пока быть занят.

`alpha` задает общую прозрачность объекта и затем умножается на fade.
В 1.0.4 её применяет принадлежащий фантому `BSFadeNode`; material alpha равна
единице. Для `alpha=1` используется ближайший меньший float, чтобы сохранить
штатный путь с глубиной и смешиванием. ABI V1 и диапазоны параметров прежние.

Цвет API задает свечение, а для `HairTint` также родной цвет волос. У
прозрачных поверхностей сохраняется исходная текстура: её цвет и мягкая альфа
по-прежнему влияют на результат. Vertex alpha игнорируется. Alpha-tested и
blended поверхности используют минимальный порог покрытия вместо исходного
положительного порога, чтобы глубина не перекрывала невидимые участки цвета
при затухании. Плотность разных материалов может отличаться.

Проход глубины предназначен для сокрытия внутренних поверхностей. Он
использует общий буфер движка, поэтому пересекающиеся фантомы могут перекрывать
друг друга. Совместимость с модифицированными шейдерами и специальными
проходами камеры ещё требует проверки в игре.

Повторная попытка относится к еще не созданному фантомy: успешная попытка
никогда автоматически не повторяется. При ошибках интервал повторов 50 мс,
deadline задан retryWindow каждого фантома. Ожидание бюджета холодного
клонирования не считается ошибкой; фиксированного времени завершения нет.

| Result | Значение |
|---|---|
| 0 Accepted | Команда принята / статус прочитан |
| 1 InvalidArgument | Неверные параметры или отсутствует обязательный аргумент |
| 2 NotReady | Игра загружается, еще не начата или геометрический backend отключен |
| 3 Capacity | Заполнено хранилище запросов / исчерпаны положительные ID |
| 4 NotFound | Неизвестный/освобожденный ID или ID прошлой игровой сессии |
| 5 Finished | Оформление завершенной/отменяемой серии уже нельзя изменить |

| State | Значение |
|---|---|
| 0 Queued | Принят, еще не обслужен |
| 1 Running | Серия или подготовка продолжаются |
| 2 Completed | Все фантомы созданы / целевая емкость подготовлена |
| 3 Partial | Часть создана, часть пропущена |
| 4 Failed | Ничего не создано |
| 5 Canceled | Отмена применена главным потоком |

`Status` содержит state, lastFailure, spawned, missed, attempts, requested.
Completed описывает завершение создания, а не окончания показа. Успешные
фантомы могут еще доживать `lifetime`. Чтобы не удалить их досрочно,
вызывать Release после fade (например, через lifetime после обнаружения
терминального статуса). Cancel/Release также можно применять к завершенной
серии, пока ее фантомы еще видны. Команды идемпотентны до обработки, но после
Release повторный вызов вернет NotFound.

Коды Failure: 0 None, 1 ActorGone, 2 No3D, 3 CloneFailed, 4 NoGeometry,
5 InvalidSkin, 6 Capacity, 7 SceneChanged, 8 SessionChanged,
9 WindowExpired. `lastFailure` сохраняет последнюю причину даже после успешного
повтора; `attempts` — реальные попытки, с насыщением UINT32_MAX. SessionChanged
зарезервирован: при сбросе сессии все ID становятся NotFound сразу.
Частично отброшенные поверхности подробно описаны в логе; usable клон может
считаться успешным. Нет доступа к живым сценовым узлам/материалам через API.

Статусы удерживаются до Release или сброса сессии и занимают MaxRequests.
ID не переиспользуются в процессе, включая загрузки. При исчерпании INT32_MAX
новые запросы отклоняются до перезапуска процесса. Нет фоновых callbacks и
сохраненных адресов кода потребителей; результат опрашивается по ID.

## Papyrus

Имя скрипта и native class — `GhostTrails`. Установить PEX; исходник находится
в `scripts/Source`. `Spawn`/`Prepare` возвращают положительный ID или
отрицательный Result. `GetRequestState` возвращает State либо отрицательный
Result. `GetStatus` возвращает `[state, failure, spawned, missed, attempts,
requested]` или массив из одного отрицательного Result. Попытки в Papyrus
ограничены представлением INT32_MAX. Управляющие функции возвращают Result
с обычным знаком: 0 значит Accepted.

```papyrus
; target — существующая переменная Actor.
Int trail = GhostTrails.Spawn(target, count = 6, interval = 0.045, lifetime = 0.4, red = 0.3, green = 0.8, blue = 1.0, spawnWindow = 0.3)
; Сохранить положительный trail; проверить GetStatus позже и вызвать Release.
```

Значения RGB `-1,-1,-1` выбирают полный default look: alpha, intensity и
rimPower в таком вызове берутся также из defaults. Чтобы задать любой из
них для одного фантома, передать явные RGB. `SetAppearance` принимает ID
серии и меняет только будущие фантомы. Название `GetRequestState` выбрано,
поскольку `GetState` уже принадлежит базовому Papyrus ScriptObject.


## Аннотации анимаций

С 1.1.0 командная часть API также доступна событиям `GT_Prepare`, `GT_Spawn`,
`GT_Color`, `GT_Stop`. Это отдельный адаптер к той же очереди запросов;
существующие потребители ABI v1 не меняются. Владение запросами адаптер берёт
на себя. См. [Annotations.md](Annotations.md) для синтаксиса и правил каналов.
