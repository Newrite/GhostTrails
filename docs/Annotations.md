# Аннотации анимаций — GhostTrails 1.1.0

Для новых событий установить Behavior Data Injector и включённый в архив
`SKSE/Plugins/BehaviorDataInjector/GhostTrails_BDI.json`. Конфиг добавляет четыре
события в проекты под `Meshes/Actors`. Если события уже добавлены behavior-патчем,
BDI не нужен. Payload Interpreter, Papyrus и ESP не требуются.

## Примеры

Строки ниже — текст аннотаций в HKX. Время задаётся средствами редактора
анимации; оно не является частью строки команды.

```text
GT_Prepare.slots=4
GT_Spawn.channel=dodge;count=4;interval=0.05;lifetime=0.6;color=0.3,0.8,1,0.6
GT_Color.channel=dodge;color=1,0.2,0.1,0.7;intensity=3
GT_Stop.channel=dodge
```

`GT_Prepare` лучше ставить заранее: он прогревает пул, но не показывает фантом.
`GT_Spawn` ставится на кадре начала следа. Для одиночного фантома достаточно
`GT_Spawn` без payload или `GT_Spawn.lifetime=0.8`. `GT_Color` изменяет только
последующие фантомы ещё выполняющейся серии. Уже созданные сохраняют свой вид.
`GT_Stop` останавливает серию и убирает её видимые фантомы при обновлении.

## Команды и параметры

Имена событий, ключей и каналов чувствительны к регистру. Событие и payload
разделяются первой точкой, параметры — `;`, ключ и значение — `=`. Пробелы
вокруг ключей и значений допускаются. Десятичный разделитель — точка.
Повторяющиеся/неизвестные ключи, лишние разделители и нечисловые значения
отклоняют всю команду без частичного применения.

| Команда | Параметры |
| --- | --- |
| `GT_Prepare` | `slots=1` — требуемая готовая ёмкость, не количество дополнительных клонов |
| `GT_Spawn` | `channel=default`, `count=1`, `interval=0.05`, `lifetime=0.5`, `retryWindow=1`, `spawnWindow=0`, `color=R,G,B,A`, `intensity`, `rimPower` |
| `GT_Color` | `channel=default` и хотя бы один из `color`, `intensity`, `rimPower` |
| `GT_Stop` | `channel=default` |

RGB и alpha в `[0,1]`, intensity/rimPower неотрицательные; `rimPower=0` выключает
ободок. Все числа конечные. Для Spawn: целое `count` от 1 до INT32_MAX,
`interval>=0`, `lifetime>0`, `retryWindow>=0`, `spawnWindow>=0`. Время в игровых
секундах, на паузе не продвигается. `spawnWindow=0` не ограничивает длительность
серии сверх конечного `count`; для длинных серий рекомендуется явный
`spawnWindow`. Prepare: `slots` от 1 до INI `SlotsPerActor`.

Spawn берёт неуказанный цвет/интенсивность/rim из текущего API default appearance
в момент обработки команды. Color сохраняет неуказанные компоненты оформления
своей серии. Аннотации не меняют глобальное оформление C++/Papyrus-потребителей.

## Каналы, время и владение

Актор — отправитель события. Канал — имя из 1..64 ASCII букв, цифр, `_` и `-`.
Одинаковые имена на разных акторах независимы. Новый принятый Spawn того же
актора и канала заменяет старую серию вместе с её видимыми фантомами. Если новая
команда отклонена, старая сохраняется. Разные каналы работают одновременно.
Каналы аннотаций не управляют запросами, созданными через C++ или Papyrus.
Prepare канала не имеет и не заменяет Spawn.

Анимационный callback копирует команду и BS handle в ограниченную очередь.
Геометрия захватывается в следующей доступной точке обновления GhostTrails,
после синхронизации кадра. Аннотация не сохраняет историческую позу ровно на
своём timestamp. Для точного визуального кадра учитывайте задержку обработки
и заранее используйте Prepare.

Серия всегда конечна по count; Stop необязателен для освобождения ресурсов.
После завершения эмиссий запрос сохраняется как минимум на lifetime последнего
фантома, затем автоматически освобождается. Prepare/неудавшиеся запросы
освобождаются после завершения. Загрузка, новая игра, выход и смена эпохи
отбрасывают старые команды и владение. В очередь и состояние не сохраняются
сырые указатели акторов, графов или строки из временного события.

Ожидающая очередь, обрабатываемый пакет и число принадлежащих адаптеру запросов
каждый ограничены `MaxRequests`; общий лимит C++/Papyrus/аннотаций также остаётся
`MaxRequests`. Переполнение отклоняется с логом, старые запросы не вытесняются.
Максимум payload — 1024 байта, чтобы ограничить разбор на потоке анимации.

События первого и третьего лица могут приходить от разных активных графов.
Повторный Spawn одного канала заменит прежний. Это явная семантика канала,
а не эвристическое удаление событий по близким timestamp.

## Диагностика и проверка

Ошибки синтаксиса, постановки в очередь и применения API пишутся в обычный лог;
причины неудачного захвата пишет существующий backend. Диагностическая DLL
дополнительно пишет принятые команды с actorHandle, каналом, именем операции
и RequestID. `GetStatus` и возвращаемые значения аннотациям не предоставляются.
Они остаются в C++/Papyrus API v1; ABI не изменён.

Добавить тестовые аннотации в одну анимацию и проверить в игре: одиночный Spawn,
серию, Color между эмиссиями, Stop, одновременные NPC, прерывание анимации,
первое/третье лицо, загрузку сохранения и переход ячейки. Пока подтверждены
сборка, тесты парсера/владения и vtable в IDA; HKX/BDI доставка требует игры.

Формат BDI: https://github.com/max-su-2019/BehaviorDataInjector/blob/master/doc/How%20to%20create%20BDI%20config%20files.md
