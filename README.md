# Ghost Trails API

Самостоятельный SKSE плагин для замороженных светящихся силуэтов акторов.
Плагин не требует Dodge, ESP, квеста или постоянного опроса окружающих NPC.
Есть C++ API через `RequestPluginAPI` и Papyrus API `GhostTrails.psc`.

Подготовлены пути **SE 1.5.97, AE 1.6.1170 и VR 1.4.15** в одной DLL.
Адреса и особенности клонирования проверены по исходникам CommonLibSSE-NG,
Dreamsleeve, Dodge и трем открытым базам IDA. Другие версии намеренно
отклоняются до установки хуков. **Проверка в запущенной игре еще требуется**:
успешная сборка и статический анализ не подтверждают визуальный результат,
безопасность сторонних мешей и отсутствие утечек в движке.

## Установка

Распаковать архив в отдельный мод MO2 или в `Data` игры:

- `SKSE/Plugins/GhostTrails.dll`
- `SKSE/Plugins/GhostTrails.ini`
- `Scripts/GhostTrails.pex`

Нужны подходящий SKSE/SKSEVR, Address Library для SE/AE, VR Address Library
для VR и Microsoft Visual C++ x64 runtime. `Source/Scripts` и `SDK` — материалы
для разработчиков. Ничего в действующую сборку модов автоматически не ставится.

## Поведение и стоимость

Пул создается только при `Spawn` или `Prepare` конкретного актора. Первый
нативный клон может занять заметное время: он не прерывается посередине.
`ClonesPerFrame=1` распределяет холодные клоны между кадрами;
`Prepare(actor, slots)` позволяет прогреть пул заранее. Подтвержденного
асинхронного снимка живой геометрии не найдено, поэтому клонирование,
сбор позы, изменение материалов и присоединение выполняются на главном потоке.
Прогретый фантом повторно использует клон и материалы, копируя текущую позу.

Все актеры хранятся по BS handle, разрешаемому в краткоживущий `NiPointer`.
После неудачного разрешения этот handle больше не опрашивается в рамках пула.
Смена корня 3D, родителя сцены или ячейки очищает старую геометрию; изменения
экипировки/структуры выявляются перед очередным созданием. Сохранения не
содержат фантомов. Загрузка, новая игра, возврат в главное меню и выход
освобождают временное состояние. Неиспользуемые пулы вытесняются по реальному
времени. Фантомы стареют по игровому времени и замирают на паузе.

Ошибочная поверхность исключается с предупреждением, остальные продолжают
работать. Ошибка клона или временное отсутствие 3D повторяются в пределах
`retryWindow` каждого фантома; после исчерпания пропускается этот фантом,
последующие попытки серии продолжаются. Недействительный handle завершает
серию сразу. Нет обещания восстановиться после access violation внутри
движка или поврежденного стороннего меша.

Число запросов, актеров и слотов ограничено INI. Лимиты считают объекты,
а не байты: размер одного клона зависит от экипировки. По умолчанию максимум
64 клона на все пулы. Активный слот не переиспользуется до завершения его
времени жизни; при нехватке емкости запрос повторяется или получает пропуск.

## Отображение в 1.0.3

Версия 1.0.2 дала подтвержденную регрессию в игре: вместо фантома временно
окрашивалась растительность. В 1.0.3 удалены прямые вызовы D3D11, преобразование
текстур и отдельный screen-door fade. Возвращен движковый путь материалов
1.0.1 с сохранением исправления инициализации rim-текстуры.

Смешивание изменено с аддитивного на обычное `SrcAlpha / InvSrcAlpha`, чтобы
уменьшить пересвет тела. Цвета текстур поверхностей с alpha test/blend
сохраняются вместе с их прозрачностью, поэтому волосы могут сохранять исходный
оттенок. Vertex alpha больше не ослабляет заданную прозрачность фантома;
порог альфа-теста уменьшается вместе с fade, чтобы волосы не отсекались раньше
остальной геометрии. Альфа текстуры по-прежнему участвует в смешивании.

Эти локальные изменения не гарантируют полное сокрытие внутренних поверхностей
при полупрозрачном отображении. Новый результат, включая волосы, обувь и
совместимость с Community Shaders/ENB, требует проверки в игре.
Устаревший `MaxCoverageMiB` из INI 1.0.2 следует удалить.

## Сборка

Нужны Windows x64, xmake 3.0.8+, современный MSVC с C++23 и локальный checkout
CommonLibSSE-NG с поддержкой всех трех рантаймов. На этой машине использованы
xmake 3.0.8 и MSVC 14.51.36231. Путь к библиотеке задается переменной
`CommonLibSSE-NG` либо опцией `--commonlib=...`.

```powershell
xmake f -y -m releasedbg
xmake build -y GhostTrails
xmake build -y GhostTrails.Tests
xmake run GhostTrails.Tests
xmake build -y GhostTrails.SDKConsumer
xmake run GhostTrails.SDKConsumer
xmake build -y GhostTrails.MaterialTests
xmake run GhostTrails.MaterialTests
```

Результат: `build/windows/x64/releasedbg/GhostTrails.dll`.
Модули `.ixx` содержат контракт и реализацию вместе; заголовок SDK нужен
для стабильного межплагинного ABI, обычные `.cpp` — для экспортов DLL/SKSE.
Общая библиотека подключается через свой xmake target; исходники библиотеки
не копируются в проект.

Подробные диагностические вызовы и измерения исключены из обычной сборки.
Чтобы получить их, собрать `xmake f -y --diagnostics=y`, затем
`xmake build -y GhostTrails` и установить `VerboseLog=1` в INI.
Такая DLL находится в `build/diagnostics/windows/x64/releasedbg`.
Обычные ошибки, причины отказа и итоги запросов остаются в обеих сборках
в `<Documents>/My Games/<runtime>/SKSE/GhostTrails.log`.
Итоги содержат `operation=Prepare` и `prepared` для прогрева без отображения;
`operation=Spawn` и `spawned` означают присоединенные к сцене фантомы.

Papyrus компилируется `housecarl_compile_script` из
`scripts/Source/GhostTrails.psc` с `out_path=<project>/dist` и каталогом
vanilla источников/flags на import path. Скомпилированный результат должен
лежать в `dist/Scripts/GhostTrails.pex`.

`tools/Package.ps1` создает обычный архив в `dist`; `-Diagnostics` собирает
архив диагностической DLL. Скрипт только упаковывает готовые результаты.

Подробные контракты и примеры: [docs/API.md](docs/API.md).
Движковые адреса и ограничения: [docs/snapshot-research.md](docs/snapshot-research.md).
Миграция потребителя Dodge: [docs/dodge-integration.md](docs/dodge-integration.md).

## Совместимость и проверка

Хуки подавления контроллеров затрагивают два проверенных вызова NiObjectNET
и устанавливаются через методы CommonLib `write_call<5/6>()`. Возвращенный
адрес сохраняется в `REL::Relocation`: у шестибайтового RIP-вызова эта версия
CommonLib возвращает слот, из которого берется указатель обработчика.
Исходный виртуальный вызов сохраняет обычный virtual dispatch. Каждый плагин
подавляет контроллеры только собственного снимка; остальные вызовы проходят
через сохраненный предыдущий обработчик. Отдельного декодера/SDK-модуля нет.

Такой же установщик внесен в исходники Dreamsleeve. Для совместимости в обоих
порядках установки нужна его пересобранная DLL: прежняя версия Dreamsleeve
сама отвергала уже измененные инструкции. Совместная работа в игре еще
требует проверки.

Перед использованием проверить на каждом рантайме: обычную/динамическую
геометрию и замороженную позу, player/NPC, первый/третий вид, переодевание,
unload/reload 3D, переходы ячеек, загрузку/новую игру, главное меню и выход,
отмену/освобождение запросов, лимиты, долгую сессию и освобождение ресурсов.
Исходники и бинарные доказательства не заменяют эти проверки.
